# W1 — the main webview's CSP and the blast radius of the command API

Part of Lanewise's first Pen-test round (pen-testing PRD §6, issue #14, label `prd:pen-test`). W1 probes the main webview, where text from repositories, Hosts, Issue Trackers and Releases is drawn and where every command is held. It starts from H1.

- **Trust boundary.** On one side is text Lanewise didn't write: Commit Messages, author names, branch and tag names, paths, Host page titles, Pull Request titles, Issue Tracker summaries, Release notes and the Changelog. On the other is the main webview that draws it. That webview holds `call`, and with it all 87 of the command API's commands (ADR 0003), besides the plugins its capability names.
- **Governed by.** `CONTEXT.md`: Hostile repository, Finding, Host page, Gateway, Model Provider, Release, Changelog. ADR 0001, ADR 0003, ADR 0035, ADR 0042, and the new ADR 0050. `SECURITY.md`. PRD §11.
- **Deliverables.**
  - A Content-Security-Policy for the main webview, in `desktop/tauri.conf.json`. The theme script runs by its hash and CodeMirror's styles by a nonce (`app/index.html`, `app/src/ui/styleNonce.ts`, and the editors in `app/src/diff/editor.ts` and `app/src/conflicts/conflictEditors.ts`).
  - The capability narrowed from `core:default` to the two core permissions the page uses (`desktop/capabilities/default.json`).
  - Tests that hold both: `app/src/platform/csp.test.ts`, `app/src/ui/styleNonce.test.ts`, and `the_main_webview_has_a_content_security_policy` in `desktop/src/lib.rs`.
  - ADR 0050, `docs/architectural-decision-record/0050-a-content-security-policy-for-the-main-webview-and-only-the-core-permissions-it-uses.md`, which is H1's dated answer.
  - A line each in `SECURITY.md`, `CLAUDE.md`, `CONTRIBUTING.md` and `docs/development.md` §4.

## How it was probed

This was done headless on Linux, in WebKitGTK 2.54.0, the engine of the Linux Desktop App. Everything was written under `/tmp` and nothing was committed but the deliverables.

1. **Read** every file the brief names, the UI's sources for every place a string reaches the DOM, and the built bundle (`vite build`) for every way a dependency could turn a string into HTML.
2. **Built the Desktop App** with `tauri build --debug --no-bundle` three times, each with the same copy of the built UI plus one test script under `/tmp`. The first build had `"csp": null`, as before. The second had a draft policy. The third had the policy as committed. The two policy builds had only a `report-uri` added, and the listener's port added to `connect-src`, so violations could be counted. Each ran under `xvfb-run` with `HOME` under `/tmp`.
3. **Opened two Hostile repositories in it.** The first was E1's `injection` fixture (`pnpm pen-test:fixtures`), a merge left in conflict with markup in its Conflict Hunk, Commit Message and author name. The second was a throwaway repository under `/tmp`, made to carry markup in a branch name, a tag name, an annotated tag's name and message, a remote URL, two Commit Messages, an author name, a committed path and an untracked path.
4. **Drove the UI through it** from the test script. It got past the Git Setup screen, opened both repositories in Tabs, chose commits, opened the Working tree's diff of a file with markup in its path in the unified view, opened the Conflicts page and its conflicted file (the Three-way view and the Resolution editor), and opened Settings. After each step it recorded the DOM: elements with an event-handler attribute, `img`, `iframe` and `script` elements, whether each payload showed as text, and how many CodeMirror editors were drawn and styled.
5. **Then injected markup and script** into the page, as a hole would, with each payload trying to reach a second local port. It tried 15 ways: an `<img onerror>` and an SVG `onbegin` through `innerHTML`, an inline and an external `<script>`, `eval`, `Function`, `fetch`, `sendBeacon`, `Image`, a stylesheet, an `iframe`, a `Worker`, a dynamic `import()`, a WebSocket and a form post.
6. **Ran `pnpm bench:graph` against the committed build** through `tauri-driver` and WebKitWebDriver 2.54.0 (unpacked under `/tmp`), on a small synthetic repository. This checked that CI's Commit graph benchmark, which drives the page over WebDriver, still works under the policy.

## Probes from the brief

### 1. Every place untrusted text reaches the DOM or an attribute

**What I read.**

- No `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `DOMParser`, `srcdoc` or `eval` anywhere in `app/src` outside tests (0 matches).
- React draws each of these as a text child, which it escapes:
  - author names: `app/src/repository/CommitHistory.tsx:960`;
  - Commit Messages: `app/src/repository/CommitDetails.tsx:169`;
  - Labels: `app/src/repository/CommitHistory.tsx:701`;
  - paths: `app/src/repository/ChangedFiles.tsx:151`;
  - Tab names, which are Host page titles: `app/src/tabs/RepositoryTabs.tsx:185`, from `desktop/src/host_pages.rs:202`;
  - Pull Request titles: `app/src/pullRequests/PullRequestsWidget.tsx:135`;
  - Issue titles: `app/src/issues/IssuesWidget.tsx:361`;
  - an Update's notes: `app/src/updates/UpdateSettings.tsx:86`.
- Where one reaches an attribute, as a Pull Request's URL in a `title` (`PullRequestsWidget.tsx:129`) or a path in a CodeMirror editor's `aria-label`, it is set as an attribute value, never parsed as markup.
- The Commit graph's Avatars are initials drawn on a canvas (`app/src/repository/graphDrawing.ts:396`).
- The Changelog is parsed by hand into React elements. Only an `http` or `https` link becomes a link (`app/src/legal/changelogMarkdown.ts:100`, with a test at `changelogMarkdown.test.ts:82`).
- A URL from a Host or an Issue Tracker is never an `href`. It is opened through `openLink` (`app/src/App.tsx:263`): in a Host page Tab, which takes only `https` (`desktop/src/host_pages.rs:112`), or in the browser, through the opener, whose scope is `https://*`. An Issue's URL is checked again in the core (`commands/src/issues/mod.rs:374`).

**What the live run showed.** With and without the policy, every payload in both Hostile repositories showed as text: the branch and tag names, both Commit Messages, the author name and the Conflict Hunk. No element anywhere had an event-handler attribute. No markup from a repository made an element. The control build without a policy got no request from any of them.

**Answer: disproved. No place was found where untrusted text reaches the DOM as markup.**

### 2. `simple-icons` SVGs and CodeMirror's language data

**What I read.**

- `simple-icons` is used once, for three logos, as path data in a `<path d>` React draws (`app/src/hosts/OpenOnHost.tsx:36`). The data is the package's own, bundled at build time, and never comes from a Host.
- CodeMirror's language data is the list `@codemirror/language-data` ships. A path chooses an entry with `LanguageDescription.matchFilename` (`app/src/diff/editor.ts:92`). Its `load()` imports a chunk from the build. Nothing is fetched from elsewhere, and under the policy nothing could be (`script-src 'self'`).
- The one `srcdoc` in the bundle is the HTML language's attribute-name table, a string.

**Answer: disproved.** Both are static data from the build, and neither is parsed as markup. The live run drew the unified diff of a `.md` path under the policy with no violation.

### 3. Whether any dependency renders HTML from a string

**What I did.** I built the UI (`vite build`) and searched all 133 chunks for every API that turns a string into HTML or code: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `DOMParser`, `createContextualFragment`, `srcdoc`, `setHTMLUnsafe`, `eval(` and `new Function`.

**Answer: disproved.** The only matches are React's own: its `dangerouslySetInnerHTML` handling, which nothing in the UI uses, and its constant `<script></script>` for making a script element, which the UI never renders. The Model Providers' SDKs touch no DOM. lucide-react draws React elements. CodeMirror writes text nodes, and its widgets set `textContent` (`app/src/diff/editor.ts:166`, `app/src/conflicts/conflictEditors.ts:108`).

### 4. What one injected script could do with `call`

**What I read.** `desktop/src/lib.rs` registers 10 IPC commands: `call`, four Update commands and five Host page commands. `call` hands any of the command API's 87 names to `lanewise_commands::call` (`commands/src/lib.rs:348`). Neither checks who is asking, because only the UI ever asks.

**Answer: as the PRD's H1 says.** The four the brief names:

| What | Through | What a script in the page could do |
| --- | --- | --- |
| Read keys | `modelProviderKey` | Read any stored Model Provider key. The UI needs it, because each Model Provider's SDK runs in the page (ADR 0020 to ADR 0024). Whether a key should cross IPC at all is S1's (#22) |
| `gatewayRequest` | `gatewayRequest` | Send a request to a saved Gateway's address, with the Gateway's headers added. Whether those headers can go anywhere else is W4's (#17) |
| The opener | `opener:allow-open-url` | Open any `https` URL in the user's browser |
| Clone and push | `startClone`, `addRemote`, `setRemoteUrl`, `startPush` | Run the system `git` with the user's own credential helpers, as the UI does (ADR 0016) |

The other commands and plugins in the capability are within reach too: the HTTP plugin to its allow-list (W3, #16), the clipboard, the folder dialog and the Host page commands. The page still can't point the updater anywhere else (`desktop/tests/updater.rs:173`).

This is the blast radius, not a way in. With probe 1 disproved, nothing reaches it. What changes it is the policy in front, which now refuses script from markup (probe 5). Making `call` itself refuse more is for the scope issues that own each command.

### 5. Whether a CSP with a hash for the theme script, or a narrower capability, would hold

**What I did.** I built the Desktop App with a policy, ran it headless, and counted every violation report through the walk in "How it was probed". I made three changes until the build's own pages raised none:

- **The theme script needs no work.** With a policy set, Tauri hashes every inline script in `index.html` as it builds and adds the hash to `script-src`. Tauri 2.12.3's `tauri-codegen` does it (`inject_script_hashes`). The live run showed it: the saved Theme was applied before the page drew.
- **CodeMirror needs a nonce.** It writes its themes into a `<style>` element, which `style-src 'self'` refused once a conflicted file was opened (one report, from `@codemirror/view`). Tauri replaces a style nonce placeholder in `index.html` with a fresh nonce each time it serves the page, and adds it to `style-src`. Passing that nonce to each editor through `EditorView.cspNonce` drew all four editors of the Conflicts page, and the unified diff, fully styled, with no report.
- **Each directive was set as a list.** Tauri's check for `'self'` misses a lone string source and would add it twice.

Then I narrowed the capability. The built UI and its four plugins call only `event|listen` and `event|unlisten` from Tauri's core, besides `set_theme` and the zoom keys the capability already names. With `core:default` replaced by those two, the walk worked as before, and `event|listen` was allowed. `app|version`, `event|emit`, `window|title` and `menu|new` were refused, each with Tauri's "not allowed" error.

**What the live run showed.**

| Build | The build's own pages | The 15 injected ways to run or send something |
| --- | --- | --- |
| `"csp": null`, as before | — | 15 of 15 ran or reached the second port |
| The policy, before the nonce | 1 report, CodeMirror's `<style>` | 0 of 15. All refused, each with its report |
| The policy as committed | 0 reports | 0 of 15. All refused, each with its report |

The Rust tests, the IPC tests against Tauri's mock runtime (`desktop/src/lib.rs`), and `pnpm bench:graph` through WebKitWebDriver all pass with both changes. The benchmark met its first-screen and layout targets on the synthetic repository, so WebDriver's scripts aren't refused.

**Answer: both hold, and both are built** (ADR 0050). They work in a source build on Linux. A Release on macOS and Windows is hand check A.

## Hypotheses this starts from (PRD §5)

| Hypothesis | Opening estimate | 12 October 2026 |
| --- | --- | --- |
| H1. Any script in the main webview has the whole command API | high | **Answered: a CSP, as defence in depth (ADR 0050).** No way for a script to get in was found (probes 1 to 3). If one ever did, the policy now refuses inline and external script, `eval`, handlers written into markup, and any load or send but its own assets, GitHub's avatars and IPC. The capability is narrowed to the core permissions the page uses. A script that ran all the same would still have `call`. Two things nearby belong to other scope issues. The policy makes one request outside the HTTP allow-list, authors' pictures (ADR 0035), part of the configuration. Whether `SECURITY.md`'s allow-list wording should say so is W3's (H5, #16). Host pages are child webviews the policy doesn't cover, and are W2's (#15).
