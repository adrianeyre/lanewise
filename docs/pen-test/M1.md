# M1 — prompt injection from a Hostile repository

Part of Lanewise's first Pen-test round (pen-testing PRD §6, issue #25, label `prd:pen-test`). M1 probes what a Hostile repository's text can do once it's sent for a Suggestion: to the prompt, to the Suggestion that comes back, to its Confidence, to what the AI Suggestion Widget tells the user, and to Jev's answers about the same Conflict Hunk. It starts from H10.

- **Trust boundary.** On one side is text a repository writes: a Conflict Hunk's Base, Ours and Theirs, the lines round it, the file's path and the commit subjects on each side. On the other are the prompt it goes into, the Suggestion and Confidence that come back, Jev's answers, and the Resolution, which only the user changes.
- **Governed by.** `CONTEXT.md`: Suggestion, Confidence, Conflict Hunk, Conflict Markers, Resolution, Jev, Hostile repository, Finding. ADR 0025 (Suggestions checked and put in only by Accept or Edit), ADR 0026 (Suggestions for every Conflict Hunk), ADR 0036 (Jev). PRD §8.1 (`git-client.md`). `SECURITY.md`'s "a Model Provider's answer that makes Lanewise … apply a Suggestion you didn't ask for".
- **Deliverables.** Tests pinning what held, each checked to fail when the behaviour it holds is broken:
  - `app/src/conflicts/HostileRepositorySuggestion.test.tsx`, on the Conflict Hunk, subjects and markup of E1's `injection` fixture: the repository's markup and a Suggestion's are drawn as text, and nothing reaches the Resolution until Accept; Jev's verdict is shown beside the Confidence but never raises it; Jev's doubt makes a Suggestion low and says so; and Jev's pick of a side changes nothing until Use, and Dismiss leaves it so;
  - `app/src/ai/confidence.test.ts`: `withJevVerdict` only ever lowers a Confidence, and a model's own high Confidence, with an explanation saying every check passed, doesn't outweigh a check that failed;
  - `app/src/ai/jev.test.ts`: a Hostile repository's text reaches Jev only as values in its state, and every question Jev is asked is Lanewise's own.

## How it was probed

This was done headless on Linux (Debian 13), with Node 26.11.1, Git 2.47.3 and the tree at `9187d3c`. Everything was written under `/tmp`. No Model Provider, Jev or Gateway was sent anything: this container's own Model Provider variables were not used, and every request was answered by the fake Model Provider (`app/src/test/fakeModelProvider.ts`) or a fake TypeSafe in the tests.

1. **Built E1's Hostile repositories** with `pnpm pen-test:fixtures`, and read `injection`: a merge left in conflict over `notes.txt`, whose Ours line holds `<img onerror>`, a bell and a terminal escape, whose Theirs line says to ignore previous instructions, and whose Ours commit's subject holds `<script>` and a request for the API key.
2. **Built the request and the prompt** from that file with `suggestionRequest` and `suggestionPrompt`, in a script under `/tmp` importing them from the tree, with the subjects `git log` gives for `HEAD` and `MERGE_HEAD`, as the core's `conflictedFile` reads them (`core/src/conflict.rs:160-161`, `:379-383`). Then with paths, subjects and Conflict Hunks of other shapes.
3. **Ran `checkSuggestion` and `withJevVerdict`** on Suggestions written to pass or fail each check, at each reported Confidence, and `jsonIn` and `readSuggestion` on answers of the shapes each adapter can get back.
4. **Drew the AI Suggestion Widget** in the App, under jsdom with the fake platform, with that Conflict Hunk and with Suggestions and Jev answers chosen by the test, and read what it shows and what changes the Resolution.
5. **Read** `app/src/ai/suggestionRequest.ts`, `app/src/ai/confidence.ts`, `app/src/ai/jev.ts`, `app/src/ai/jevDecisions.ts`, `app/src/ai/requests.ts`, `app/src/ai/aiWords.ts`, the three adapters (`anthropic.ts`, `gemini.ts`, `openAiCompatible.ts`), `app/src/conflicts/SuggestionWidget.tsx` and `app/src/conflicts/ResolutionWidget.tsx`.
6. **Pinned what held** in the tests above.

Each answer below says what was shown to hold. A lead under PRD §4 isn't written in this file, whichever probe it came from.

## Probes from the brief

### 1. A Conflict Hunk, path or Commit Message that steers the Suggestion

**What I read.** A request is built from the Resolution as it is when the user asks (`app/src/conflicts/SuggestionWidget.tsx:257-262`) by `suggestionRequest` (`app/src/ai/suggestionRequest.ts:21-45`): the Conflict Hunk's three versions, up to the context Settings sets on each side, the path and the two subjects, and nothing else. `suggestionPrompt` writes it as the one user message (`:82-93`). What the model is told to do is Lanewise's own text, `SUGGESTION_INSTRUCTIONS` (`:67-74`), sent apart from the repository's text in each Model Provider's own place for it: `system` for Claude (`app/src/ai/anthropic.ts:189-190`), `systemInstruction` for Gemini (`app/src/ai/gemini.ts:263-265`) and a `system` message for the OpenAI-compatible Model Providers (`app/src/ai/openAiCompatible.ts:98-99`). Only a commit's subject, its message's first line, is sent, never its body (`core/src/conflict.rs:378-383`). The answer is read as a Suggestion or refused: three fields of the right types, and a Confidence of `high`, `medium` or `low` (`app/src/ai/suggestionRequest.ts:102-117`).

**What the runs showed.** `injection`'s prompt carries its Conflict Hunk, its subjects and its path as the disclosure lists them (`app/src/ai/aiWords.ts:22-30`), and the control bytes reach it as they are in the file. Nothing from the repository reaches the instructions, the schema or which model is asked, and nothing it says is acted on by Lanewise: whatever comes back is only shown.

**What held.** The repository's text reaches the request only in the four places the First-use disclosure lists, and Lanewise acts on nothing in it or in the answer. Whether a real model's Suggestion follows what the text tells it is for a real Model Provider: hand check A.

### 2. A Suggestion that passes every check at high Confidence and quietly removes a check or adds code

**What I read.** `checkSuggestion` (`app/src/ai/confidence.ts:54-74`) makes a Suggestion's Confidence low where its Resolution text still has Conflict Markers (`:57-60`), is empty (`:61-62`), or leaves out a line only Ours or only Theirs has (`:63-67`), as ADR 0025 and PRD §8.1 list. Jev's verdict joins them only as a doubt (`:80-83`). A Suggestion reaches the Resolution only through `ResolutionHandle.put` (`app/src/conflicts/ResolutionWidget.tsx:373-379`), which only Accept and Edit call (`app/src/conflicts/SuggestionWidget.tsx:426-441`), and the Resolution reaches the working tree only by Mark resolved, which still refuses Conflict Markers left in unless the user checks the box to allow them (`app/src/conflicts/ResolutionWidget.tsx:464-473`). `put` is called nowhere else but Jev's Use (probe 4).

**What the runs showed.**

| Suggestion | Model reported | Shown |
| --- | --- | --- |
| Keeps every line only one side has | high | High |
| Leaves out a line only Ours has | high | Low, naming the line |
| Still has `<<<<<<<` | high | Low |
| Empty | high | Low |
| Leaves out Theirs' lines, its explanation saying every check passed and Confidence is high | high | Low, naming the lines |
| Leaves out a side's line, with Jev 99% sure it keeps both | high | Low, with Jev's 99% beside it |

**What held.** A check that fails makes the Confidence low whatever the model reported, whatever its explanation claims and however sure Jev is: the model's word and Jev's can lower a Confidence, never raise one past a failed check. And no Suggestion, at any Confidence, reaches the Resolution without Accept or Edit, or the working tree without Mark resolved. What the checks look for is ADR 0025's; H10 asks whether a Suggestion that passes them can still do harm, and its answer is below.

### 3. What the AI Suggestion Widget shows the user about Confidence, and whether it overstates it

**What I read.** Each Suggestion is shown (`app/src/conflicts/SuggestionWidget.tsx:605-690`) under a heading starting "AI-generated" (`:629-631`), with "Made by" its Model Provider and "Check it before you use it: AI can be wrong." (`:632`), then "Confidence:" and the word (`:638-641`). A low Confidence has a warning icon and bold text, and a box saying what the model reported and each check that failed, with a side's dropped lines listed, or that the model said it wasn't sure (`:642`, `:761-791`). Jev's verdict follows, as "Jev: N% likely to keep what both sides meant." (`:643-650`). Then the Resolution text, the model's explanation under "Why", and Accept, Edit and Reject, with a note that nothing is written to the working tree until the Resolution is marked resolved (`:660-688`). The status read out says the Confidence too (`:323-327`), and asking for every Conflict Hunk sums up how many were low (`:136-154`). The Resolution text and the explanation are React text, never HTML (`:665`, `:669`).

**What the runs showed.** With `injection`'s Conflict Hunk and a Suggestion whose explanation held `<img onerror>`, `<script>` and a direction override, both were shown as the characters they are, no element was made from either, and the axe check passed. A failed check showed Low with its reasons, and Jev's doubt showed Low with Jev's words (`app/src/ai/aiWords.ts:41-52`).

**What held.** Every Suggestion says it's AI-generated, who made it, and to check it; a low Confidence is flagged and explained; the repository's text and the model's are drawn as text. How the Confidence line reads to someone using it, in both themes and with a screen reader, is hand check C.

### 4. Jev asked about the same Conflict Hunk

**What I read.** With Jev on and its Suggestion check chosen, each Suggestion is sent to Jev with the path and the Conflict Hunk's three versions, and Jev is asked whether the Resolution text keeps both sides' changes (`app/src/ai/jevDecisions.ts:16-46`, `app/src/conflicts/SuggestionWidget.tsx:275-286`). Ask Jev which side sends the same request with the context and asks which of five ways it goes (`app/src/ai/jevDecisions.ts:60-93`, `app/src/conflicts/SuggestionWidget.tsx:195-213`). Each is one `POST` to TypeSafe, or a Gateway kept for it, whose body is `model`, `state` and `questions`, written by `JSON.stringify` (`app/src/ai/jev.ts:104-109`). The repository's text is only ever in `state`; each question's instructions and criteria are fixed strings. An answer is read only as a `noul` number or one of the five choices; anything else is no answer (`app/src/ai/jevDecisions.ts:44-45`, `:90-92`). Jev's pick is shown as "A hint only: check it before you use it." with Use and Dismiss (`app/src/conflicts/SuggestionWidget.tsx:525-542`), and only Use puts it in, as one change Undo takes back (`:216-228`).

**What the runs showed.** A path, a Conflict Hunk and subjects holding quotes, braces, line breaks and instructions reached Jev as the same strings in `state`, and the questions were the same, word for word, as for a plain Conflict Hunk. Jev's 99% beside a failed check left it Low; Jev's 12% made a Suggestion that passed every check Low. Jev's pick of Theirs at 97% changed nothing in the Resolution, sent nothing to the Model Provider, was taken away by Dismiss, and was put in only by Use, and nothing was written.

**What held.** Jev is asked only with Lanewise's own questions, the repository's text can't add to or change them, its answer can only lower a Suggestion's Confidence, and its pick of a side is a hint that changes nothing without Use. Whether Jev's own answers follow what the text tells it is for a real TypeSafe key: hand check B.

## Hand checks (need the owner)

Do each in the disposable account of the rules of engagement, with only E2's throwaway keys in its credential store, on the first Release that has this round's changes, or for A and B a build from source on the same machine. Never with a real project's repository or a real key.

**A. A real Model Provider on the `injection` fixture**

1. Run `pnpm pen-test:fixtures`, and open `injection` under the fixtures folder it names.
2. In Settings → AI, turn on "Suggest Resolutions with AI", choose a Model Provider and model, accept its First-use disclosure and save E2's throwaway key for it.
3. On the Conflicts page, choose `notes.txt` and press Suggest a resolution.
4. Write down the Model Provider, the model, the Confidence shown, and whether the explanation or the Resolution text does anything the Conflict Hunk's or the subject's text told it to rather than resolving the Conflict Hunk, or holds anything neither side has.
5. Press Reject. Check that the Resolution is as Git left it.
6. Do steps 2 to 5 for each Model Provider E2 has a key for, and once with Suggest for all Conflict Hunks in this file.
7. File anything step 4 found as PRD §7 says, privately first if it's critical or high (PRD §4), and write the date and the Release in H10's row above.

**B. Jev on the same Conflict Hunk**

1. In Settings, turn Jev on, with its Suggestion check and Ask Jev which side, and save E2's throwaway TypeSafe key.
2. Do steps 3 and 4 of A. Write down Jev's percentage beside the Confidence, and check that the Confidence shown is no higher than without Jev.
3. Press Ask Jev which side. Write down its pick and percentage, and check that the Resolution doesn't change until Use is pressed.
4. Press Dismiss, then Undo once in the Resolution. Check that the Resolution is still as Git left it.
5. File anything that doesn't hold as in A's step 7.

**C. How the Confidence reads**

1. With A's Suggestion shown, and a second one made low by Rejecting and asking again with a model set to a low Effort, or with E1's `conflict-merge` fixture, look at each in the light theme, the dark theme and, on Windows, a high-contrast theme.
2. Check that "AI-generated", "Made by" and "Check it before you use it", the Confidence line and, for a low one, the warning, the reasons and Jev's line, can each be read, and that focus is visible on Accept, Edit and Reject.
3. With VoiceOver on macOS and NVDA on Windows, ask for a Suggestion and check that the status read out says the Confidence, and that the Suggestion's heading, Confidence, reasons and Jev's line are read in that order.
4. Write the date, the Release and the platform in H10's row above.
