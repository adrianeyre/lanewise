# S3 — the Logs and Diagnostics

Part of Lanewise's first Pen-test round (pen-testing PRD §6, issue #24, label `prd:pen-test`). S3 probes what Lanewise writes about itself, and what Copy diagnostics puts in the public bug-report form. It starts from H9.

- **Trust boundary.** On one side is what Lanewise writes to the Logs: its own records, whatever the UI sends with `writeLog`, and every panic. On the other are other accounts on the same computer, which could read the Log files, and the public bug-report form on `adrianeyre/lanewise`, which Copy diagnostics fills in and the user submits.
- **Governed by.** `CONTEXT.md`: Logs, Diagnostics, Finding, Hostile repository. ADR 0028. PRD §11 (no telemetry). `SECURITY.md` ("How Lanewise protects what it holds").
- **Deliverables.** Defence in depth in `commands/src/logs.rs`, each with a test that was checked to fail when its rule is broken:
  - `keys_and_tokens_are_hidden_by_their_prefixes` and `a_token_is_hidden_after_anything_but_a_letter`: the redactor knows GitLab's other tokens, Atlassian's for Jira and Bitbucket, Trello's and Azure DevOps', and finds a token after `_`, a digit or `%22` too;
  - `a_line_writes_out_what_would_change_how_it_reads`: a line keeps no control character, such as a terminal's escape, and no Unicode line break or direction mark, but writes each out as `\u{…}`;
  - `the_logs_are_kept_to_their_user`: on macOS and Linux the log folder is `0700` and its files `0600`, including ones made before with more.

  ADR 0028 and `SECURITY.md` say so.

## How it was probed

This was done headless on Linux (Debian 13), with Rust 1.99.0, `tokio` 1.53.1, `regex` 1.13.1, `os_info` 3.15.0, Tauri 2.12.3 and Git 2.47.3. Everything was written under `/tmp`. No token was a real one, and nothing was sent to a Host, Model Provider, Issue Tracker or Gateway, or to GitHub's bug-report form.

1. **Read** `commands/src/logs.rs`, `commands/src/diagnostics.rs`, `desktop/src/lib.rs`, every `log` macro in `core`, `graph`, `commands` and `desktop`, every `unwrap`, `expect`, `panic!` and slice outside tests in those crates, every caller of `writeLog` in the UI, `app/src/diagnostics/`, `app/src/settings/DiagnosticsSettings.tsx` and `.github/ISSUE_TEMPLATE/bug-report.yml`.
2. **Ran the command API's `call`** from a program under `/tmp`, built against `lanewise-commands`, with the Logs started in a folder under `/tmp`. It opened all nine of E1's Hostile repositories (`pnpm pen-test:fixtures`) and read each one's status, working tree changes, Branches, Stashes, In-Progress Operations, Commit graph and history, and every commit's details, files and diffs, each file's diff in the working tree and as a conflicted file, and a merge preview by each local branch: 352 commands, besides the reads that listed what to read next. It then sent `writeLog` canary tokens of each shape below, control characters, a 5 MB message, Markdown and requests it doesn't take, called commands that don't exist, caught a panic, and read `diagnostics` back.
3. **Pinned what held**, and hardened what the brief asks about, in the tests above.

Each answer below says what was shown to hold. A lead under PRD §4 isn't written in this file, whichever probe it came from.

## Probes from the brief

### 1. Tokens without a prefix the redaction knows: Atlassian, Trello, Azure DevOps, Bitbucket

**What I read.** The Logs keep secrets out first by what's logged, and only then by `redact` (ADR 0028). What reaches the Logs at all:

| What's logged | Where | What it can hold |
| --- | --- | --- |
| A command that failed, by its name and its error's `kind` | `commands/src/lib.rs:348-354`, `commands/src/logs.rs:179-201` | A command's name and a fixed word |
| A request that was rejected | `commands/src/logs.rs:190-197` | The name it was called by, but never the request or serde's message |
| An `internal` rejection, with its message | `commands/src/logs.rs:198`, `commands/src/lib.rs:468`, `desktop/src/lib.rs:55` | A serializer's error or a panic's message (probe 2) |
| The Desktop App's start and version, the Git Setup by kinds, an Update's failure by its kind | `desktop/src/lib.rs:70`, `commands/src/setup.rs:140`, `desktop/src/update.rs:180`, `:297` | Versions and fixed words |
| Each panic, with its message and where it was | `commands/src/logs.rs:63-75` | Probe 2 |
| Whatever the UI sends with `writeLog` | `commands/src/diagnostics.rs:55-58` | Probe 3 |

Jira's, Trello's, Bitbucket's and Azure DevOps' tokens are only ever in the OS credential store, the request the core makes, and Git Credential Manager (S2). None of the rows above is built from them: an Issue Tracker's or Host Integration's failure is logged by its `kind`.

**What the runs showed.** Before this round, `redact` (`commands/src/logs.rs:146`) knew `sk-`, `xai-`, `AIza`, GitHub's and `glpat-`, and a token named as one (`token=…`, `Bearer …`, `Basic …`). Canaries shaped as an Atlassian API token (`ATATT…`), an Atlassian access token (`ATCTT…`), a Bitbucket app password (`ATBB…`), a Trello token (`ATTA…`), an Azure DevOps token (with `AZDO` in it) and GitLab's runner and deploy tokens (`glrt-`, `gldt-`), each sent bare through `writeLog`, were kept as sent. So was a known key after `_` or `%22`, since the pattern started at a word boundary. Each is now hidden (`commands/src/logs.rs:116-126`), and these lines read back as `***` in `diagnostics`, since a line is redacted again as it's read (`:86-108`).

Some tokens have no shape a redactor can know: Trello's older 64 hexadecimal digits look like a SHA-256 object ID, Azure DevOps' older 52-character tokens are lowercase letters and digits, and Meta's, a local Model Provider's and Jev's keys have no published prefix. ADR 0028 says so: they're kept out by what's logged.

**Answer.** No path was found by which an Issue Tracker's or Host's token reaches the Logs. The redactor, the second line, now knows every one of the four the brief names that has a prefix, and the rest are kept out by the first.

### 2. Panic and internal-error messages built from untrusted text or file contents

**What I read.**

- **Lanewise's own panics.** Every `expect` outside tests in `core`, `graph`, `commands` and `desktop` says a fixed sentence (`commands/src/gateway.rs:163`, `commands/src/page.rs:96`, `commands/src/history.rs:115`, `commands/src/issues/trello.rs:129`, `:135`, `graph/src/lanes.rs:284`, and the patterns in `logs.rs`). Every slice of a string is cut where `find`, `char_indices` or an ASCII separator says (`core/src/sign_in.rs:75`, `core/src/branch.rs:542`, `core/src/git/progress.rs:66`, `core/src/git/credentials.rs:21-58`, `commands/src/hosts/answer.rs:154`, `core/src/commit_actions.rs:632`). An index out of range would say two numbers.
- **What a panic's message says.** The hook logs a panic's message and its place (`commands/src/logs.rs:63-75`). `call` in the Desktop App turns a command's panic into an `internal` rejection with `tokio`'s `JoinError`, which repeats the message (`desktop/src/lib.rs:55`; `tokio` 1.53.1, `src/runtime/task/error.rs:143`). Both go through `redact`. Rust 1.99's panic for a string cut inside a character says the character and its bytes, not the string.
- **Other `internal` rejections.** Only one is made in `commands`: a response or error that can't be turned into JSON (`commands/src/lib.rs:468`). serde's message for that names the problem, not the value.

**What the runs showed.** The 352 commands on the nine Hostile repositories, including `paths` (a terminal-escape filename and `..`), `injection` (markup, control bytes and a prompt in a Commit Message, a Conflict Hunk and an author) and the four left in conflict, wrote 85 lines to the Logs. Every one was a command's name and its failure's `kind`, such as `conflictedFile failed: notConflicted`. None panicked, none was `internal`, and no path, ref, Commit Message, author or file's contents reached the Logs. A caught panic cutting a string inside `é` was logged without the string.

**Answer: disproved for Lanewise's own code.** No panic or `internal` message in it is built from a repository's text or a file's contents. A dependency's panic would be logged with its message, which is why a line is redacted and written out on one line; none was seen.

### 3. `writeLog` with whatever the UI sends

**What I read.** `writeLog` takes a `level` of `error`, `warn` or `info` and a `message`, and nothing else (`commands/src/diagnostics.rs:20-34`). It logs the message under `lanewise_ui` (`:55-58`), so every line the UI writes says it's the UI's. The UI's own callers send an uncaught error's name and stack frames, never its message (`app/src/diagnostics/log.ts:22-33`), and a failed Suggestion's Model Provider and `kind` (`app/src/ai/requests.ts:161`). A command that doesn't exist is logged by the name it was called by (`commands/src/logs.rs:190`), so it carries the UI's text the same way. Only the main webview can call either: a Host page reaches no command (W2), and ADR 0050's policy keeps any other script out of the main webview (W1).

**What the runs showed.**

| Sent | Kept |
| --- | --- |
| A canary of each shape in probe 1 | `***` |
| `level: "debug"`, or a field it doesn't take | Rejected, and logged as rejected, without the request |
| 5 MB of one character | One line, cut at 2,000 characters and `…` |
| Text with `\n`, `\r\n` and `\r` | One line, each written as `\n` |
| A terminal's escape and bell, NUL, DEL, a C1 control, U+2028, U+2029 and a right-to-left override | Before: as sent. Now: each written out as `\u{…}` |
| A Markdown code fence, a mention and an image | As sent, after the line's time, level and `lanewise_ui:` (probe 5) |
| A command named with a canary token or an escape | The same as through `writeLog` |

The Logs never take more than about 4 MiB (`commands/src/logs.rs:35-41`), so a page that wrote enough could push older lines out. That needs a script in the main webview, which has the whole command API anyway (W1).

**Answer.** Whatever the UI sends is one line, redacted, at most 2,000 characters, marked as the UI's, and now with nothing in it that a terminal or an editor would act on rather than show.

### 4. The Log files' permissions on each OS

**What I read.** The Desktop App starts the Logs in Tauri's `app_log_dir` (`desktop/src/lib.rs:62-76`): `~/Library/Logs/com.adrianeyre.lanewise` on macOS, `%LOCALAPPDATA%\com.adrianeyre.lanewise\logs` on Windows and `~/.local/share/com.adrianeyre.lanewise/logs` on Linux (Tauri 2.12.3, `src/path/desktop.rs:296-308`). `RollingFiles` made the folder with `create_dir_all` and the file with `OpenOptions`, giving neither a mode, so each took the process's umask.

**What the runs showed.** With the usual umask of `022`, the folder was `755` and `lanewise.log` `644`: readable by any account that could reach the folder. On macOS, `~/Library` is normally the user's alone, so another account couldn't; on Linux, it depends on the home folder. Now the folder is set to `0700` and each file to `0600` whenever the Logs start, including ones made before (`commands/src/logs.rs:299-305`, `:352-362`). A file rolled over keeps its mode. On Windows the folder takes `%LOCALAPPDATA%`'s access list, which by default gives only the user, the system and administrators access.

**Answer.** On macOS and Linux, only the user can open the Logs, whatever the umask or the home folder, and the test holds it. Windows is hand check A, and so is macOS on a Release.

### 5. What Copy diagnostics puts in the public form

**What I read.** `diagnostics` (`commands/src/diagnostics.rs:117-141`) returns the operating system, its version and the processor from `os_info`; the Git version, never its path (`:153-164`); Git Credential Manager's version, the first line `git credential-manager --version` writes, run in the OS temp folder, not a repository (`core/src/setup.rs:234-248`), and whether it's a credential helper; the log folder; and the latest 50 lines, redacted again. The UI's `diagnosticsText` adds the Lanewise version and leaves the log folder out (`app/src/diagnostics/diagnostics.ts:30-41`). `bugReportUrl` puts the text in the `diagnostics` field of `https://github.com/adrianeyre/lanewise/issues/new?template=bug-report.yml`, encoded, and drops the oldest lines to keep the link to 8,000 characters (`:49-54`). Settings copies the text and opens the link in the browser, and nothing is sent (`app/src/settings/DiagnosticsSettings.tsx:45-54`). The form shows the field as `render: text`, a code block, and says to take out anything the user would rather not share (`.github/ISSUE_TEMPLATE/bug-report.yml`).

**What the runs showed.** `diagnostics` after the runs above: `Debian 13.0.0 (x86_64)`, Git `2.47.3`, no Git Credential Manager, and 50 lines: commands' names and kinds, the UI's lines with the canaries hidden, the panic, and the folder, which the text leaves out. The text names no account, home folder, repository, path, branch, Remote or Host.

Every line of the text starts with a label of Lanewise's own (`Lanewise:`, `Operating system:`, …) or a log line's time, since every line the logger writes does (`commands/src/logs.rs:230-244`), and a line holds no line break. So nothing in it can start a line with the three backticks that would end the form's code block, and the Markdown the UI sent in probe 3 shows as text.

What it does hold, which the user reads before submitting: the times Lanewise was used, in UTC, which commands failed, the versions, and an `internal` rejection's or a panic's message, which ADR 0028 says may name a path.

**Answer.** Copy diagnostics puts versions and up to 50 redacted lines in the form, sends nothing, and leaves the log folder out. Nothing found in it is a secret. Hand check B checks the form on a Release. In Web Mode, the same command would hand the log folder and lines to whatever reaches the server, which is PRD §9's question for P1 (#32).

## Hand checks (need the owner)

Do each on macOS and on Windows, in the disposable account of the rules of engagement, on the first Release that has this round's changes.

**A. Only the user can open the Logs**

1. Install the Release, open it, and open and close a repository, so the Logs are started.
2. On macOS, in Terminal, run `ls -ld ~/Library ~/Library/Logs/com.adrianeyre.lanewise ~/Library/Logs/com.adrianeyre.lanewise/*`. Check that the folder is `drwx------` and each file `-rw-------`.
3. On Windows, in Command Prompt, run `icacls "%LOCALAPPDATA%\com.adrianeyre.lanewise\logs"` and `icacls "%LOCALAPPDATA%\com.adrianeyre.lanewise\logs\lanewise.log"`. Check that only the account, `SYSTEM` and `Administrators` are listed.
4. On each, sign in as a second, standard account on the same machine and try to open `lanewise.log` by its full path. Check that it's refused.
5. Write the date, the Release and the platform in H9's row above.

**B. What Copy diagnostics puts in the form**

1. In the same Release, open a folder that isn't a repository, so `openRepository` fails and is logged.
2. In Settings → Diagnostics, choose Copy diagnostics.
3. In the browser that opens, check that the bug-report form's Diagnostics field shows the Lanewise, operating system, Git and Git Credential Manager versions and the latest lines, as a code block, and nothing that names the account, its home folder, the folder you opened or any other path.
4. Paste the clipboard into a text editor. Check it's the same text, with up to 50 lines.
5. Close the browser's tab **without submitting**.
6. Write the date, the Release and the platform in H9's row above.

**C. A real token of each shape is hidden** (a build from source, since a Release has no devtools)

1. In the same account, clone `adrianeyre/lanewise` and run `pnpm desktop:dev`.
2. Right-click → Inspect, and in the Console run `window.__TAURI_INTERNALS__.invoke("call", { name: "writeLog", request: { level: "info", message: "shape <token>" } })` once for each of E2's throwaway Jira, Bitbucket, Trello and Azure DevOps tokens, in place of `<token>`.
3. Open `lanewise.log` in the folder Settings → Diagnostics names. Check that each line says `shape ***`. For one that doesn't, write down which Issue Tracker or Host it is from, not the token.
4. Delete those lines from `lanewise.log`, and revoke and make again each throwaway token, since it was typed into a console.
