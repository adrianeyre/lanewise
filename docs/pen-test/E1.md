# E1 — the fixtures: a script that makes Hostile repositories

Part of Lanewise's first Pen-test round (pen-testing PRD §6, issue #10, label `prd:pen-test`). This is an **enablement** scope issue: it builds what the G, M and S3 scope issues probe with, and probes no trust boundary of its own.

- **Trust boundary.** None. A Hostile repository (`CONTEXT.md`) is the bait the rest of the round opens, clones, fetches and resolves conflicts in; E1 only makes it.
- **Governed by.** `CONTEXT.md`: Hostile repository, Conflict Hunk, In-Progress Operation, Stash. PRD §3 (synthetic data, rules of engagement).
- **Deliverable.** `app/scripts/pen-test/buildFixtures.ts`, run by hand with `pnpm pen-test:fixtures`, with `git.ts` (the plumbing) and `fixtures.ts` (the builders) beside it, and `buildFixtures.test.ts` pinning what it makes.

## How it is built, and why nothing fires on the builder

Every repository is synthetic, made from nothing by the system `git`; none is a real project's history (PRD §3). The dangerous paths — `..`, absolute symlink targets, case collisions — are written **straight into the object database** with `hash-object`, `mktree` and `commit-tree` (`app/scripts/pen-test/git.ts`) and **never checked out**, so a path that would escape the working tree exists as an object without ever being written to the builder's own disk. The only commands a configuration names write a marker file under one directory and nothing else, and are armed **after** everything is committed, so building a fixture runs none of them (`app/scripts/pen-test/fixtures.ts`, `configAndAttributes`). The test asserts the marker directory never appears while building (`buildFixtures.test.ts`, "building the fixtures fires nothing").

Output goes to a folder under the OS temp directory by default, so the worktree stays clean and the fixtures sit outside it (PRD §5 rules of engagement: write outside `/tmp` and the worktree never).

## Probes from the brief

Each is a fixture. "Read" points at where it is built.

| Probe | Fixture | What it makes | Marker that shows it worked |
| --- | --- | --- | --- |
| refs and tags whose names start with `-`, or hold odd but valid characters, in `packed-refs` and on a remote | `refs-and-tags` | Branches `-u`, `--output=pwned`, `--upload-pack=touch`, tags `-n` and one with an invisible separator, a homoglyph branch and an emoji branch, written into `.git/packed-refs` and into a crafted local remote with its own objects (`fixtures.ts:refsAndTags`, `git.ts:appendPackedRefs`) | `git for-each-ref` lists a branch `-u` and a tag `-n`, here and on the remote |
| paths with `..`, absolute paths, symlinked folders, and case collisions for Windows and macOS | `paths` | A tree naming `..`, `sub/..`, symlinks to an absolute path and to a climbing path, a `README`/`readme` collision, a leading-dash file, a backslash path, a reserved `CON`, a trailing dot-and-space, and a terminal-escape filename — committed, never checked out (`fixtures.ts:paths`) | `git ls-tree` shows the entries; the working tree holds only `.git` |
| `.git/config` and `.gitattributes` naming filter drivers, `core.fsmonitor`, `core.sshCommand`, `remote.*.uploadpack` and a credential helper, each of which only writes a marker file | `config-and-attributes` | A filter driver, a diff `textconv`, `core.fsmonitor`, `core.sshCommand`, a credential helper, a remote `uploadpack` and a `post-checkout` hook, each writing one marker (`fixtures.ts:configAndAttributes`, `git.ts` — armed after commit) | A marker file appears under the marker directory when Lanewise runs the matching operation; an empty directory means nothing ran |
| merges, rebases, cherry-picks and reverts left in conflict, including conflicts on symlinks and on paths of the kinds above | `conflict-merge`, `conflict-rebase`, `conflict-cherry-pick`, `conflict-revert` | Four repositories each left mid-operation at a conflict over a text file, a symlink and an odd-but-valid filename (`fixtures.ts:conflictOperation`, `conflictingHistory`, `addSymlinkConflictSides`) | `git status` reports the operation in progress, and `.git` holds `MERGE_HEAD`, `rebase-merge`, `CHERRY_PICK_HEAD` or `REVERT_HEAD` |
| Commit Messages, author names and Conflict Hunks carrying markup, control characters and prompt-injection text | `injection` | A merge left in conflict whose Conflict Hunk holds `<img onerror>` and control bytes, whose Commit Message holds `<script>` and a prompt-injection instruction, and whose author name carries a control and a bidi-override byte (`fixtures.ts:injection`) | `git status` shows the conflict; the hunk, message and author carry the payloads |
| submodules with hostile URLs and paths | `submodules` | A `.gitmodules` naming an `ext::` transport (which runs a command), an option-looking URL, a `file://` source and a path that climbs out of the superproject, with the hostile submodule paths left as gitlinks (`fixtures.ts:submodules`) | `git show HEAD:.gitmodules` names the `ext::` URL and the climbing path |

Two facts of the system `git` shaped the fixtures, and are worth knowing for the probes that use them (neither is a Lanewise behaviour):

- Git strips `<` and `>` from an author name, so markup in an author name cannot survive; the `injection` fixture puts markup in the Commit Message and the Conflict Hunk, and control and bidi-override bytes in the author name.
- `git mktree` takes one path component per entry, so `sub/..` is built as a sub-tree whose entry is named `..`.

## Hypotheses this enables (PRD §5)

E1 starts from no hypothesis of its own; it is the pre-condition for the ones the G, M and S3 issues answer. Recorded here so each has a home:

- **H6** (opening a Hostile repository runs what it says) — `config-and-attributes` is its instrument. Dated answer: owed by G1 (#18).
- **H7** (a ref name chooses an argument) — `refs-and-tags` is its instrument. Dated answer: owed by G2 (#19).
- **H10** (a Conflict Hunk can write its own Suggestion) — `injection` is its instrument. Dated answer: owed by M1 (#25).
- **G3 / G4** (writes by a hostile path; clone URLs, transports, submodules) — `paths`, the conflict family and `submodules` are their instruments.

## Hand checks (need a Release, and macOS or Windows)

This sandbox has no screen, no macOS and no Windows, and no Release (PRD §7). The fixtures are built and checked headless on Linux here; the probes that open them in Lanewise are for the scope issues, on a Release, in a disposable account. The steps each of those runs:

1. On a disposable machine or user account, build the Release's Desktop App (`pnpm desktop:build`) and run `pnpm pen-test:fixtures`.
2. Note the marker directory the script printed, a new `lanewise-pen-test-markers-*` folder in the OS temp folder, which starts empty.
3. Open each Hostile repository under the folder the script printed, a new `lanewise-hostile-fixtures-*` folder in the OS temp folder unless `--out` named one, in Lanewise, do nothing else, and read each repository's own README for the marker to watch.
4. After opening, fetching, diffing and resolving, check whether any marker file appeared, whether any path escaped that folder, and whether any name reached the UI as markup. File anything that did as a Finding (PRD §7); hold a critical or high one privately first (PRD §4).
